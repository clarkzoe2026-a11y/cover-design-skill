同批蓝色候选经过独立 AI 设计审查与字重调整，但不把暖色新版的确认当成蓝色候选单独通过。早期过空／过满候选和实操文章 v1–v8 不记为验收。样本与提示词保存在外部试作目录，不将私人材料复制成公开包内示例。

16:9 基线来自通过样本：深色信息包围框同口径测量约52%与57%，过空候选约36%–39%。因此把约50%–58%作为复核提示，而非墨色覆盖率或自动通过条件。长标题、其他比例与指定布局需要重新协调；这些样本不能证明所有主题与比例均已通过。

## 内容与决策演练

以下为明确标注的虚拟输入，仅作文本层演练，不声称生成了图片。

| 输入 | 期望决策与演练结果 |
| --- | --- |
| 仅标题《给阳台种一盆会开花的香草》 | 标题逐字保留，不加身份／结论／流程；默认一张4:3，香草生长隐喻，不套用视频转换机器 |
| 实操摘要：旧收据按月份分类、录入金额、汇总核对成支出表 | 标题表达收据整理成月表，流程来自分类／录入／汇总／核对，不把摘要未提及的拍照硬加为步骤；各层不硬凑 |
| 同主题只把“按年份”改为“按地点”，背景再浅一点 | 以指定现有图编辑，只变指定文字与背景；保留深字、强调色、构图与比例，另存版本 |
| 同主题要求三个版本，再换色 | 4:3、3:4、16:9分别重排，共用文案与配色；换色只变配色，不把一次通过套给三个版本 |
| 给文章链接，但正文无法读取 | 说明读取缺口，不冒充读过文章，不默默退成仅标题任务 |

正文短标题与仅标题逐字保留是两个分支；精准压缩不能删改用户锁定原话。内嵌例句也使用从属字重，不能成为另一处粗黑标题。

## 发布前校验

- `scripts/check_package.py`：元数据、本地链接、公开文本隐私与示例真实像素／哈希。
- `unittest discover -s tests -v`：现有五项包检查测试。
- 官方 skill-creator `quick_validate.py`：使用已有带 PyYAML 的 Python 环境执行。此前默认 Python 缺依赖的失败仍保留在历史记录，不用精简版结果冒充官方校验。
- `git diff --check`：补丁格式；安装副本逐文件比较（WorkBuddy 仅允许既有元数据差异）。
